# 决策模板 — ADR (Architecture Decision Record)

> **何时用**: 任何**重大决策** + 多方案对比 + 不可逆影响 + 影响 ≥ 1 个月的项目状态。
> **门槛**: 满足以下 ≥ 2 条才用:
> 1. 不可逆(切 prod / 选 BI 工具 / 改认证策略)
> 2. 影响 ≥ 1 个月
> 3. 涉及多个有道理的方案
> 4. 未来 agent 重做时必须知道当时为什么
>
> **不要用**: 单步重构 / 临时修 / 选谁都不影响的小决策。
> **配套**: ADR 标准起源 — Michael Nygard《Documenting Architecture Decisions》。

## 命名规范

`../_decisions/YYYY-MM-DD-<short>.md`,例如 `2026-10-15-decision-evidence-core-keep.md`。

---

## 1. Context(背景与约束)

**问题**: 一句话描述要决策的事。

**背景**:
- 当前状态如何(必填)
- 触发该决策的具体事件(可选)

**约束**:
- 时间预算 / 团队规模 / 数据规模 / 安全合规 / 成本上限

---

## 2. Considered Options(候选方案)

每个方案写一行"做什么" + "优势" + "劣势":

### Option A: <名称>

- **做什么**: ...
- **优势**: ...
- **劣势**: ...
- **风险**: ...

### Option B: <名称>
...

### Option C: <名称>
...

## 3. Decision(决定)

> **我们选 Option X(名称)**。

**关键理由**(3-5 条):
1. ...
2. ...
3. ...
